# Operating guide

Evaluator V3 runs inside Claude Code. Claude Code (the main session) is the orchestrator; stage subagents in `.claude/agents/eval-*.md` do the thinking; deterministic TypeScript (`npm run ev`) validates every hand-off; hooks in `.claude/settings.json` log and police tool use outside the model. No API key is needed.

## Setup

```bash
cd evaluator-v3
npm install
npm test          # deterministic modules + hooks
```

Start a **new** Claude Code session in the repository after pulling, so the `eval-*` agents, the `evaluate` / `eval-bench` skills and the hooks are loaded.

Optional: allow full-page fetching. In this cloud environment WebFetch is blocked by the network policy, so web evidence is limited to search results (classified at most CORROBORATED/INFERRED unless the page is fetched). To allow fetching, widen the environment's network access; then start runs with `--webfetch yes`.

## Evaluate a new subject

In Claude Code: `/evaluate <your question, with context and any documents>`.

Or by hand:
1. Put the request in a file and any supporting documents somewhere readable.
2. `npm run ev -- run:new --request-file request.md` (copy documents into `runs/<RUN>/sources/` before the research stage).
3. Follow `.claude/skills/evaluate/SKILL.md` step by step.

Outputs in `runs/<RUN>/`:

| file | what |
|---|---|
| `report.md` | the evaluation, evidence table, and validation record |
| `validation-record.json` | 8 required fields, generated by code from the tool log |
| `tool-log.jsonl` | every search / fetch / read / subagent call (hook-written) |
| `plan.json`, `research.json`, `evidence.validated.json`, `packet.json` | stage outputs |
| `draft-N.json`, `review-N.json`, `gates-N.json` | each analysis cycle |
| `revisions.jsonl`, `stages.jsonl` | revision reasons; stage timeline |

## Reading a result

- **Certified: NO** means at least one quality gate failed after the allowed revisions, or a critical defect remains. Read section 8 of the validation record.
- **Evidence classes** are recomputed by code: a claim marked VERIFIED by the agent is shown as `INFERRED (claimed VERIFIED)` if its source was only a search snippet. Rejected evidence cites a source that was never retrieved during the run.
- **Independent validation status** is "NOT INDEPENDENTLY VALIDATED" unless a separate grader process has graded the run (benchmark only).

## Budgets and limits

Defaults: 12 web searches, 8 fetches, 2 revisions per run (`run:new --max-searches/--max-fetches/--max-revisions`). The guard hook denies calls past the budget; denials appear under "checks not executed". Known defect: parallel calls issued together can overrun the budget by a few (see docs/results.md).

## Benchmark

See `.claude/skills/eval-bench/SKILL.md`. Held-out cases are sealed by `bench/heldout.MANIFEST.sha256`; `run:new` refuses held-out cases whose hashes changed.

## Security boundaries

- Stage subagents are read-only (Read/Glob/Grep; the researcher also WebSearch/WebFetch). Enforced twice: agent `tools:` frontmatter and the guard hook (per agent type, and per declared stage for any subagent).
- Retrieved content is treated as data; prompt-injection resistance is measured by canary checks, not assumed.
- Nothing in the pipeline deploys, writes outside `evaluator-v3/runs/`, or holds credentials.
